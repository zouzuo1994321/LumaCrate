## ✨ 它是什么

一个**本地优先**的 Windows 桌面影视管理软件：借鉴 Emby 的海报墙 / 演员 / 详情页，以及 tinyMediaManager 的本地管理与强化关联搜索。全部界面用 PySide6 实现，PyInstaller 打成**单个 exe**，双击即用。

- **纯本地、不联网刮削**：只读取影片目录里已刮削好的 `.nfo`，不访问任何在线元数据服务；片单、番号、演员信息完全留在自己机器上。
- **演员 / 导演独立成表（Emby 模式）**：`people` 表独立存储，可从任意演员 / 导演反查其全部作品。
- **单文件 exe**：`--onefile --windowed`，无需安装、无需 Python。

## 🚀 下载与运行

**无需安装 Python、无需联网、不依赖浏览器。**

1. 到 [Releases](../../releases) 下载 `流明盒-v1.46.8-2610230110.exe`（约 57 MB，单文件）。
2. 双击运行 —— 首次启动会在 **exe 同目录** 生成 `index_data/`（索引库）与 `settings.json`。
3. 运行期数据生成在 **exe 同目录**，可随 exe 一起移动。

> ⚠️ 因为是 PyInstaller 单文件 exe，部分杀软会误报。源码完全开放，可自行核对或从源码构建。

## 🖱️ 怎么用

- **建立媒体库**：工具 → 媒体库 → 新建媒体库，添加本地影片目录（建议目录内已备 `.nfo`）。
- **扫描建索引**：保存后软件读取 nfo 建立本地索引（演员 / 导演 / 标签等）。
- **浏览**：海报墙按媒体库 / 收藏 / 合集切换；演员库、导演库可反查作品。
- **智能推荐**：
  - 向量编辑 → 从画像自动填充 / **从收藏的演员自动填充**，调出你的内容偏好；
  - 推荐墙「引导向量」输入艺人名 / 标签，临时偏向往某方向。
- **AI 引擎**（可选）：基础工具 → AI引擎设置，开启「自动拉起 Ollama」或点「立即启动」，检测本地引擎后在下拉选调用模型。

## 🎨 界面上的几处讲究

这些细节是「流明盒」观感与稳定性的来源，单独拎出来说明。

### ① 冻结式布局：窗口恒定、内容不重排

工具窗固定默认 **1320×960**，打开即这个尺寸；窗口仍可手动拖拽（下限 560px，只为不把左侧导航挤没）。每页绘制在固定宽 **1170px** 的画布上（= 1320 − 150 导航），拉宽窗口只在右侧留白、组框宽度一字不变；拉高时多余高度落在页面脚下，子模块高度锁定、不随窗口膨胀。这套「滚动区 → 固定宽画布 → 页面」三层结构（v1.40.7 引入）彻底消除了「切页窗口自己跳高矮 / 内容被硬切」两类老问题。

### ② 强调色派生：12 色任选、全链路统一

「外观」里 12 种高亮色可选。运行日志底色、进度环、选中流光、启动画面进度条全部由 `rgba(__ACCENT__, …)` 派生（HLS 空间只调明暗 / 饱和度），改一处全链路跟着变，不会出现「某块颜色还是写死的旧色」。

### ③ 执行日志与运行日志同款样式（v1.40.11）

「工具 → 演员刮削 → 执行」的日志框与「工具 → 数据与日志 → 运行日志（实时）」统一为同一套样式：等宽字体（Consolas / Courier New / monospace）+ 半透明深色底 `rgba(0,0,0,0.25)` + 浅色字 `#d9cfbf` + **不自动换行**。两条框共用同一个 `LOG_BOX_STYLE` 常量，观感一致、改一处两处同变。（仅样式复刻，执行框仍显示实时 `[i/total]` 进度行，不做 app.log 实时 tail。）

### ④ Fusion 风格守卫：真机才画得出控件

Windows 11 默认的 `windows11` QStyle 是四个风格里**唯一画不出 `QTreeView::indicator`** 的——演员检测的复选框在离屏（`offscreen`）后端全绿，真机却整列空白。修法：`main.py` 建完 `QApplication` 立刻 `setStyle(QStyleFactory.create("Fusion"))`。立下铁律：**凡是验「控件是否真画出来」的探针，必须在 `QT_QPA_PLATFORM=windows` 下跑**，离屏与真机结论可差出一个 QStyle。

### ⑤ 数据统计与实时状态面板

侧栏底部「数据统计」与「实时状态」面板均可在「外观」里开关。实时状态走**进程级单例**采集线程（CPU / 内存 / 网络 / GPU / Ollama，含 psutil 优先 + ctypes 兜底降级链），避免面板重建时连带销毁运行中线程导致进程崩溃（v1.27.0 真机缺陷的根治）。

## 🔍 核心功能深挖

### 6️⃣ 演员刮削与 Cloudflare 验证助手

「工具 → 演员刮削」提供全量 / 增量 / 补齐 / 修复四种模式，仅补齐演员资料并下载头像，不修改任何媒体文件。代理有**显式开关**（关闭 = 纯直连，不读系统代理）；站点连接失败时给出 **TCP → TLS → HTTP 正文（WAF 挑战页）→ 应用层** 四层判因，并按数据源指出针对该站挑战机制的出路。Cloudflare 验证助手用**内置 WebView2 浏览器**过一次人机校验（窗口置顶 + 即时反馈），cookie 自动取回注入并复用，也可单独点「读取 Cookie」复查，无需 F12。

**方案B · 内置浏览器常驻抓取会话（v1.41.3，默认关，opt-in）**：minnano 的 TLS 握手被掐（WinError 10054）、IMDB 命中 AWS WAF 挑战页——这些拦的是 Python/curl 进程的 TLS/JA3 指纹，cookie 跨不过去。为此新增「用内置浏览器抓取」开关：开启后对某个源点一次「站点验证」，过完校验的 WebView2 窗口**不销毁**、改当常驻抓取会话；刮削请求在无头路径失败时回退到这个浏览器会话用 `fetch()` 取 HTML（复用真 Chromium 的 TLS 指纹与 cookie 罐），取回的 HTML 与无头完全一致、解析逻辑一行不改。开关默认关闭，不影响历史行为。

**新增女优数据源 avbase.net（v1.42.0）**：minnano 常被 TLS 拦截、IMDB 只覆盖普通影人——为 AV 女优补一个**字段最全**的替代源。avbase.net 按日文名直达资料页 `/talents/<姓名>`，解析「基本情報」面板取 **生日 / 出身地 / 身高 / 三围罩杯 / 趣味**，外加姓名后的假名注音（罗马音）与 DMM 头图，一次补齐多字段。源列表可在「工具 → 演员刮削」里勾选 / 排序，`config.load()` 会把新源自动追加进老配置并默认启用（无需重置）。

**数据源行高压紧（v1.42.1，反馈）**：源列表三行由 56px 收紧到 44px、行内上下边距 4→2、组间距 7→5，描述文字单行完整显示不裁切，源列表与「刮削策略」之间及页面下方不再留白。

**新增三个资料源 + gfriends 独立头像源（v1.43.0，需求 4）**：资料源从 3 个扩到 6 个——**Wikipedia（日文）**（官方 API，取生年月日 / 身长 / 三围 / 出身地 / 别名 / 首段简介 + 官方头图，实测三上悠亜 生日 1993-08-16、身高 159cm、出身地 愛知県名古屋市中区）、**ThePornDB**（公开 API，只认英文 / 罗马音，日文名会先做假名→罗马音转写再查；匿名访问已被官方关闭，需在刮削策略里填个人 API Key，留空则该源自动跳过）、**JavDB**（生日 / 身高 / 三围齐全，但全站 Cloudflare WAF，需开启「用内置浏览器抓取」并先做站点验证）。**头像独立源 gfriends**（github.com/gfriends/gfriends）与资料源分离：它是纯头像图库（约 10 万张、10GB），用仓库根目录 `Filetree.json`（4.8MB，本地缓存 7 天）按姓名索引，图片直链走 `Content/<图库目录>/<真实文件名>` —— **路径必须 URL 编码**（中文名不编码会 404）；资料源都没给头像时按姓名补一张。

**演员库清理（v1.43.0，需求 3）**：「工具 → 演员刮削」顶部新增「演员库清理…」——列出**没有任何作品关联**（works=0）的演员 / 导演记录（反复刮削、改名、合并、删片后的残留），可勾选批量删除。只清索引（`people` + 作品关联），**不动头像文件、不动任何媒体文件**；收藏 / 置顶的人默认不列入；列表默认全部不勾选，必须自己勾或点「全选」才会删。

**数据源列表只露三行 + 滚轴（v1.43.1 / v1.43.2）**：源多到 6 个后，列表固定只显示 **3 行**（44×3+8=140px），其余用右侧竖向滚轴翻页；滚轴给该列表单独加粗（槽加极淡底、handle 32% 白、悬停变高亮色），一眼就能看出「下面还有」。滚动条最初被写死为 `ScrollBarAlwaysOff`（那时列表按行数长高、永远装得下），v1.43.2 改回 `AsNeeded`。

**「其他数据源」：把内置浏览器指到你自己的站点（v1.46.5，反馈）**：数据源列表下方新增一行单选 —— **Cookie 目标：自动** ⇄ **其他数据源 + 网址框 + 测试**。「自动」沿用老行为（对已启用源里排在最前的那个取 cookie）；选「其他数据源」并填上网址后，点「**Cookie 获取…**」会**先用内置浏览器打开这个网址**，你在里面过完人机校验（登录 / Cloudflare / AWS WAF），回到对话框点「获取 Cookie」，cookie 就注入到这个 host —— 于是不在内置 5 个源里的站点也能复用同一套浏览器会话。网址保存时自动补 `https://`、去掉根路径尾巴，只接受 http/https（脏值直接不进配置）；旁边的「测试」用该站点已注入的 cookie 发一次轻量请求，给出「可用 / 未获取 / 已失效」三种结论。

**拖动条统一为「虚线 + 五点 grabber」（v1.43.3）**：演员检测页（竖向高度条 + 树↔详情横向条）与图像检测页（结果树↔详情）现在共用同一个自绘把手 `_GripHandle`：沿拖动方向画一条 1px **虚线**（`CustomDashLine[3,4]`，暗白；悬停/拖动提亮），**五个圆点**（跟站点高亮色、带极淡深色描边）压在虚线中段。两种拖法——在点簇以外按住 = 原生调分栏宽高；**在点簇上（±18px）按住 = 把点簇沿虚线滑到新位置、不改分栏**（悬停时点簇换成四向光标并浮出淡色胶囊，提示「能抓」）。

**横向拖动条同款 5 点把手 + 数据源幻影空槽兜底（v1.42.2，反馈）**：演员检测页「结果树↔右侧详情」的**横向**拖动条换成与竖向完全相同的 5 点 grabber（自绘把手方向感知：横向把手 5 点竖排、竖向把手 5 点横排，同大小、同提亮效果）；演员刮削页数据源列表增加幻影空槽兜底（重建时清掉没有挂 widget 的幻影数据源行），并修复 `QListWidget.clear()` 不删除 `setItemWidget` 行控件导致的控件堆积与结果标签悬空引用。

### 7️⃣ 智能推荐与引导向量

推荐算法简化为「普通 / AI 单选 + 引擎状态 + 检测」；引导向量支持**模糊匹配**（含子串的标签 / 片商 / 系列全部加强），并可**中文自动翻译成日文再匹配**（轮奸 → 輪姦、三上悠亚 → 三上悠亜）。向量编辑支持「从画像自动填充」与「从收藏的演员自动填充」，可选统计范围 / 取前 N / 权重 / 逐维度启用并记住偏好。

### 8️⃣ 演员检测（罗马音归并 + AI 复核 + 多选批量合并）

普通算法做罗马音归并 / 别名互指，AI 算法（本地 Ollama，可选依赖）复核「不同艺名同一人」。结果树左侧「选择」复选框列支持 **Shift 区间 / Ctrl 逐点**多选，一键把勾选的「建议合并」簇按各自默认保留艺名批量合并（`db.merge_people`，只补空字段 + 合并别名与 meta，不动视频 / nfo）。结果树与底部编辑区之间的竖向拖动条为**主流 5 点 grabber**（v1.42.1，自绘把手：横向 5 圆点，颜色跟高亮色、悬停变亮）；结果树↔右侧详情之间的横向拖动条同为 5 点 grabber（v1.42.2，方向感知：横向把手 5 点竖排，与竖向同大小同效果）。

### 9️⃣ 画像概览（高频榜 / 分布 / 八维偏好雷达）

基于收藏画像的高频标签 / 片商 / 系列 / 演员 / 导演榜，配八维偏好雷达图。长 CJK 条目名用**像素级**对齐（按 `QFontMetrics.horizontalAdvance` 真实宽度预算，而非字符数），计数右对齐、条形用当前高亮色，杜绝折行 / 溢出 / 重叠。

### 🔟 单文件 exe 与本地优先架构

PyInstaller `--onefile --windowed` 打成单个 exe；刮削只读本地 `.nfo`，不联网。演员库 `people` 表独立（Emby 模式），可从任意人物反查作品；数据库层用 SQL 下推 + 增量渲染扛 5W+ 片，排序与索引逐列对齐避免每页全表扫描。

### 1️⃣1️⃣ 元数据管理与隐私

「工具 → **数据与日志**」分四块：**元数据导出 / 导入**（整库快照 or 按内容分类导出）、**偏好管理**、**运行日志**、**运行日志（实时）**。（v1.43.0 曾把导航改名为「元数据管理」，v1.43.1 按反馈改回「数据与日志」；页内分组仍用「元数据」这个说法。）

**偏好管理（v1.43.0，需求 2）**：只搬「**你的偏好**」，与文件路径无关——影片**收藏 / 观看次数 / 用户评分**（按**番号**归一化存储：`MIDE-823` 与 `mide 823` 都能对上；同一番号的多副本一起更新），以及演员库 / 导演库里**收藏与置顶**的人（按姓名 + 角色）。备份是单个 JSON、跨版本可读；导入是**逐条合并**（只 UPDATE 偏好字段，不删数据、不覆盖资料字段，可反复执行），导入时**用户评分同时写回 nfo 的 `<userrating>`** —— 所以 nfo 被重新刮削覆盖之后，也能一键把评分找回来。换目录、换电脑、重装系统后导入即可恢复。

全部索引、设置、日志生成在 **exe 同目录**（可随 exe 移动）；导出 / 导入支持数据备份与四页扫描结果续接。所有数据留在本机，不向任何在线服务上报；AI 引擎提示词做脱敏（不含盘符 / 目录 / 番号 / 文件名）。

### 1️⃣2️⃣ 详情页演员/导演头像交互（v1.40.14 · v1.40.15）

详情页「演职人员信息」区的头像：**左键单击**或**双击**均进入该演员/导演的详情页；**右键**弹出「输入框 + 联想」搜索框——输入即跨**演员库 + 导演库**按姓名 / 别名 / 罗马音实时联想，单击选中联想项或输全后回车确认，**即把当前影片该位演员/导演替换为所选人**（就地改写该作品的 `media_people` 关联并即时刷新「演职人员信息」，不跳「工具」界面）。同一部作品里若所选人已存在则自动去重合并，其它作品的关联不受影响。演员与导演都可作为替换目标——`db.search_people` 同时检索两库，`db.replace_media_person` 只改这一部作品。

搜索弹层的**外观**（v1.40.15）：一块**无边框统一面板**——没有系统标题栏；标题「替换「XX」」就在面板正文首行，右侧是明确的 **「放弃修改」** 按钮（= 取消，不改动本片，等同 Esc / 点面板外）。

## 🛠️ 开发与打包

### 环境

- Python 3.13 + PySide6（Qt 6）+ PyInstaller 6.x
- 可选：`psutil`（本机指标，含 ctypes 兜底，可安全进单文件 exe）、`curl_cffi`（浏览器 TLS 指纹，降级链可选依赖）、Ollama（本地 AI 引擎，可选）

### 常用命令

```bash
# 源码态直接跑
python src/main.py

# 打成单文件 exe（产出 流明盒-vX.Y.Z-YYMMDDNNNN.exe，落到根目录与 history/）
python build_exe.py
```

- 打包参数（`--onefile --windowed`、图标 `logo.ico`、捆绑 `logo-4.png`）写在 `build_exe.py`，不用命令行长参数。
- 最新版 exe 放根目录，历史版本自动归档到 `history/`。

### 排障

- **杀软误报**：PyInstaller 单文件 exe 常被误报，源码开放可自行核对或从源码构建。
- **构建号自增**：每次 `build_exe.py` 会把 `version.py` 的 `BUILD_SEQ` 末四位 +1（跨日连续、不按日归零），并同步顶部注释、README 徽章与下载名。
- **离屏平台陷阱**：离屏 `offscreen` 后端默认 QStyle 是 `windows11`（画不出 `QTreeView::indicator`），必须在 windows 后端子进程里量控件像素才可信。
