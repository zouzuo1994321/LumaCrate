# 流明盒 (LumaCrate)

> **所有流明 · 尽收盒中** —— *Every lumen, in one crate.*

![Build](https://img.shields.io/badge/build-2609210040-success.svg)

一个**不依赖浏览器、不依赖网页**的本地影视管理桌面软件。借鉴 Emby 的海报墙与演员管理模式，借鉴 tinyMediaManager 的本地管理思路，并重点强化了**片名 / 类型 / 演员的关联搜索**。影片刮削功能已阉割：仅读取已被 Emby / tinyMediaManager / Kodi 刮削好的 `.nfo`；演员信息独立保存，并可选通过 `www.minnano-av.com` / `IMDB` 单独补齐。

> 原名「本地影视中心 / LocalMediaCenter」，**v1.27.0 起更名为「流明盒 / LumaCrate」**（功能不变，只是品牌与界面文案）。

## 核心特性

- **纯桌面程序**：PySide6 原生界面，无 Web 服务、无浏览器依赖，双击 exe 即用；默认窗口 1920×1080。
- **本地播放器直接播放**：点击播放时直接调用本机播放器（VLC / MPV / PotPlayer / 系统默认关联），解决 Emby 必须网页播放的痛点。
- **读取已刮削的 nfo**：支持 `movie.nfo` / `tvshow.nfo` / 分集 `.nfo`，并识别 **tinyMediaManager 式单项刮削**（`番号.nfo` + `番号.mp4` + `番号-poster.jpg`），提取标题、年份、简介、评分、用户评分、上映日期、类型、分级、画质、海报、背景图。
- **首页列表 + 详情**：列表列可由设置自由勾选、**按住表头拖动排序**（含「演员」列），鼠标悬停某行会在光标旁弹出**缩略图预览卡**。
- **独立演员库（Emby 模式）**：演员信息单独存于 `people` 表，可与任意作品关联；演员页可**反查全部作品**。
- **关联搜索（解决 tinyMediaManager 弱项）**：支持按片名、类型、演员联合搜索，演员→作品双向跳转。
- **媒体库全部自定义**：媒体库只有一份列表，**没有内置库** —— 新建时由你自己命名、指定类型与媒体文件夹；侧边栏右键可 编辑 / 重命名 / 扫描（新增·补缺·覆盖三种模式）/ 删除（弹窗确认，**不动磁盘文件**），删除后不会自动恢复。
- **文件夹里直接扫描**（v1.13.0）：在「文件夹」页对某个媒体库**右键**即可选择「扫描新添加和修改的 / 扫描全部补充缺失 / 扫描全部并覆盖」；扫描前会**先统计出视频文件数量供你确认**，再开始并**显示扫描进度**（可随时取消）。
- **海报墙每行 8 个**（v1.13.0）：影片墙固定每行 8 张卡片。
- **按页读取 + 读取进度（v1.14.0）**：影片墙与演员库不再一次性把所有条目读进内存并建控件 —— 数据在数据库层**分页查询**，卡片**分批增量渲染**（每批 60 张，批间把控制权交还事件循环）；滚到接近底部或点「加载更多」继续，载完显示「共 N 部（已全部载入）」。**v1.18.0 起加载过程中不再显示计数 / 进度读条**（数万部规模下长期停在 0% 显得像卡死），卡片本身增量出现即是最直观的进度反&#x9988;**。**&#x35; 万条规模下也不再一进库就未响应。\**
- **媒体库名称后显示影片总数（v1.14.0）**：侧边栏每个媒体库条目显示为「库名（N）」，媒体库页标题显示「库名（N 部）」；计数由一次 `GROUP BY` 查询得出，不做逐库统计。
- **影片墙筛选 + 排序（v1.14.0）**：影片墙顶部一条工具栏 —— 排序菜单（名称 / 类型 / 添加时间 / 上映日期 / 年份 / 评分 / 用户评分 / 收藏 / 时长 / 文件大小 / 观看次数 / 最近播放 + 升降序，当前项打勾，参考 Emby 的排序菜单）；筛选下拉覆盖**收藏情况、用户评分（有/无、≥3/5/7/9）、年份（2020·2010·2000 之后 / 2000 及以前）、类型、画质（4K/1080P/720P/HDR10/杜比视界/Atmos）**，可叠加、可一键重置。**筛选与排序全部在 SQL 层完成**，偏好写入 `settings.json` 下次自动恢复。
- **演员库筛选 + 排序（v1.14.0）**：演员库同样带工具栏 —— 筛选：收藏情况 / 置顶 / 状态（现役·退役·未知）/ 有无头像；排序：作品数 / 最新作品 / 姓名 / 生日 / 收藏 / 置顶 / 加入顺序 + 升降序（置顶恒在最前）。
- **演员库 / 导演库每行 6 个（v1.28.1）**：两个人物库的卡片网格由每行 5 个改为**每行 6 个**（两库共用同一种网格类型，一处调整同时生效，1920 默认窗下 6 列宽 1476px、放得下不挤）。**海报墙仍是每行 8 个、文件夹仍是 6 个**，互不影响。
- **设置（v1.24.0 起叫「工具」）窗口不再阻塞主界面（v1.14.0）**：设置改为**非模态**窗口 —— 设置开着时主界面照常浏览、搜索、切页、播放；重复点「工具」把已开的窗口抬到最前；设置里扫描媒体库的进度**就地显示**（不再弹模态「扫描完成」窗），关主窗口会一并关掉设置窗。
- **演员刮削补齐**：工具 → 演员刮削，可用 `www.minnano-av.com` / `IMDB` 补齐演员别名、生日、罗马音、简介与头像，支持优先级、启停、限速、代理与进度中断。
- **数据导出 / 导入 + 日志导出**（v1.13.0）：工具 → 数据与日志，可把「已处理与扫描过的信息」（媒体索引 + 演员资料 + 媒体库配置）打包导出为 zip，日后导入用于**恢复数据库**（导入前自动把现有数据另存为 `*.bak-<时间戳>`）；软件的全部运行记录写入 `index_data/logs/app.log`，可一键导出压缩包用于排错。**v1.24.0 起支持按分类勾选导出**（见下）。
- **运行日志实时显示（v1.19.0）**：工具 → 数据与日志 的「运行日志（实时）」面板，每隔约 1.5 秒自动刷新、滚动显示 `app.log` 的尾部内容（最多 200KB，自动滚到最底），直接告诉你软件当前在做什么、扫描 / 刮削进度如何（关闭窗口即停止刷新）；原 v1.18.0 的「数据库统计汇总」面板已移除。
- **详情页操作按钮清晰可见（v1.20.0）**：「收藏 / 评分 / 刷新 / 更多」叠在明亮的剧照横幅上，改用**深底 + 鎏金描边 + 亮字**的专用样式（`QPushButton#HeroAct`），不再像旧版那样融入背景看不清。
- **详情页「刷新」单片重扫（v1.20.0）**：详情页操作行&#x7684;**「刷新」**&#x6309;钮只重新读取**本片**对应的 nfo 并即时刷新本页（`scanner.rescan_one`）—— 外部工具改了 nfo 后无需重扫整个媒体库；**收藏 / 播放次数不受影响**，nfo 未写 `<userrating>` 时库中已有的用户评分也会保留；选集 / 分集的结构（parent_id / season / episode）不会被重扫打散。
- **卡片左下角一键收藏（v1.21.0）**：海报卡片**左下角**新增收藏星标 —— **已收藏 = 金色实心五角星**，**未收藏 = 白色描边 + 内部透明**的五角星（能透出海报）。点一下即切换收藏，与详情页走同一份数据（`db.toggle_favorite`），并同步刷新左下角统计与侧边栏计数，不必进详情页。
- **卡片播放按钮图标居中（v1.21.0）**：右下角圆形播放键的三角形原先用字符「▶」绘制，字形左右边距不对称、在圆圈里始终偏左；改为**几何绘制多边形**并把三角形**重心**对齐圆心，视觉得以真正居中。
- **首页流畅度优化（v1.21.0）**：针对首页卡顿定位到三处根因并逐一解决 —— ① 悬停列表行时**磨砂底衬被反复重算**（换一次要整窗缩放 + 模糊，鼠标一动就卡）→ 改为**按作品 id 去重 + 130ms 去抖**；② 表格分批填充时每格都触发重绘 → 一批 200 行包在 `setUpdatesEnabled(False)` / `blockSignals` 里，**一批只重绘一次**；③ 搜索框**每敲一个字符就整表过滤重填** → 加 250ms 去抖；另外给磨砂底衬的原图缓存加了**上限（LRU 6 张）**，避免悬停浏览大量剧照后内存持续上涨。
- **重复影片检测（v1.23.0）**：设置 → 重复检测，找出**同一部作品在多个目录里各存了一份**的情况 —— 身份键优先用番号（归一化为 `abc123`），没有番号则回退「标题 + 年份」；**同目录的多份一律视为分片（CD1/CD2）自动排除**，只有跨目录才算重复；按「保留最大的一份」估算**可回收空间**，并给出**极高 / 高 / 中 / 低**四级置信度。可按媒体库与最低置信度过滤，结果可导出 **CSV / JSON**。算法移植自姊妹项目 [NFO 画像矿工](https://github.com/zouzuo1994321/nfo_profiler) 的 `dedupe` 模块（详见文末「相关项目」）。
- **演员详情页状态按钮完整显示 + 就地收藏 / 置顶（v1.23.0）**：演员详情页的「现役 / 退役 / 未知」三个状态按钮改用专用紧凑按钮（全局 `padding:7px 14px` 会把 26px 高按钮的内容区压到 12px，字形上下被裁）；演员名字右侧新增 **☆ 收藏 / △ 置顶** 两个按钮，与 `people` 表的 `favorite` / `pinned` 字段双向同步，点一下即生效。
- **exe 文件图标与侧栏品牌（v1.23.0）**：打包时用 `--icon logo.ico` 把 logo 写进 exe 的 **PE 图标资源**（资源管理器里看到的就是自定义图标），并由 `setWindowIcon` 覆盖任务栏 / Alt-Tab / 标题栏；侧边栏品牌区改为 **logo 与软件名（现为「流明盒 / LumaCrate」）横向平齐**（原先 logo 竖排在上、把导航整体挤下去）。
- **蓝色启动动画（v1.24.0，v1.27.0 加 Slogan）**：启动时显示 **440×344** 的自绘启动画面 —— 深蓝底 + 蓝色渐晕 + logo + 软件名与英文名（现为「流明盒 / LumaCrate」）+ **Slogan** + **真实进度条（带百分比）** + 当前步骤提示 + 版本版权，进出各带淡入淡出；进度对应真实启动阶段（检查环境 → 打开索引 → 载入样式 → 统计媒体库 → 就绪）。设 `LMC_NO_SPLASH=1` 可跳过。
- **画像概览（v1.24.0，v1.24.1 加统计范围）**：工具 → 画像概览，后台算一遍你的口味并给出**一句话画像**、**八维偏好雷达**（标签广度 / 艺人专一度 / 片商忠诚度 / 高清偏好 / 长片偏好 / 打分积极度 / 系列收集度 / 追新度）、**高频榜**（标签·演员·导演·片商·系列）、**分布**（画质 / 评分 / 时长 / 年份 / 入库月）与**标签共现**。**统计范围可选「全部媒体库 / ★ 我的收藏 / 各媒体库」**，换范围立刻重算；演员与导演的关联条数**按所选范围统计**，不会出现「100 部作品 / 5.7 万条关联」这种口径错乱。算法移植自 [NFO 画像矿工](https://github.com/zouzuo1994321/nfo_profiler)。
- **智能推荐 + 向量编辑（v1.24.0，v1.24.1 修渲染）**：导航新增 **智能推荐** —— 依&#x636E;**「我的收藏」里的影片**（标签 / 片商 / 系列 / 演员 / 导演加权）与**演员库里收藏的人**建立偏好画像，对候选池做余弦打分（带 IDF 降权、共现扩展、MMR 去重），每张卡都写明**推荐理由**，可「换一批」。**推荐墙与「全部」页同一套卡片**：海报正常显示、**左下角 ☆ 收藏 / 右下角 ▶ 播放**都在（v1.24.1 修掉了「只有星标、没图、没播放键」）。工具 → 智能推荐 里可选 **普通智能算法** 或 **AI 智能算法**（走**本地离线 Ollama**，探测不到就自动回退内置算法，**不联网、不外发**）；「**检测本地 AI 引擎**」点下去会立刻显示「正在检测…」，并给出**带时间戳**的结论（✅ 检出 / ⚠ 未检出 / ❌ 失败）与排查指引（v1.24.1 之前点了看不出任何变化）；「向量编辑」可按维度给关键词加/减权重（−5 ~ +5），正数加权、负数屏蔽。
- **导演库（v1.24.0，v1.24.1 修跳页，v1.28.1 精简卡片）**：分类 → 导演库，参考演员库的卡片与筛选排序，但**不显示生日 / 出生地 / 身高 / 胸围 / 三围**（导演资料里基本没有），卡面只留 **作品数 / 别名**，双击可反查该导演的全部作品。**v1.28.1 起去掉了「简介」一行、卡片高度由 160px 压到 118px** —— 真机 1218 位导演的 `bio` 几乎全空，留着只是每张卡都印一排「—」白占高度（详情页仍会显示简介，此处只精简卡片）。**在导演库点 ☆ 收藏 / ▲ 置顶后原地重排，不会再跳回演员库**（v1.24.1 修）。
- **合集改为影片墙样式（v1.24.0）**：合集页与「我的收藏」一样是**海报卡片墙**（前 2 张海报拼贴 + 合集名 + 共 N 部），点击进该合集的影片墙，分页增量加载。
- **侧栏扫描进度环（v1.24.0）**：正在扫描 / 刷新的媒体库，其名称右侧显示一个**圆形进度环**（弧长即进度、无进度时自转），悬停可见百分比，扫完自动隐藏。
- **按分类导出 / 导入（v1.24.0）**：工具 → 数据与日志 可**勾选要导出的分类**（影片索引 / 演员与导演资料 / 关联 / **影片收藏** / 观看次数 / **用户评分** / **演员收藏与置顶** / 界面设置…），换机器时只搬轻量信息即可；导入时若含 `sections.json` 则**合并**进当前库，否则按整库快照处理（先自动另存 `*.bak-<时间戳>`）。
- **重复检测的三处改进（v1.24.0）**：点「开始检测」**先清空上次结果再重算**；**磁盘上已被删掉的索引行不再参与比对**（超过 90% 缺失视为盘未挂载，放弃剪枝以防误伤）；「同目录分片」是否自动排除**可开关**，结果改为**可展开的树**、**双击任一副本即在资源管理器中定位**文件。
- **AI 模型可自选（v1.25.0）**：工具 → 智能推荐 的「调用模型」可以直接填本机 Ollama 里的任意模型名 —— 就是命令行 `ollama list` 第一列那个名字（例如 `qwen2.5:7b` / `llama3.1:8b` / `qwen3:4b`，**冒号和标签都要带上**），点「读取本机模型」把本机已装的列出来、点一下即填入；留空则自动取本机第一个。**填了但本机没装**不会闷声失败：立刻降级为内置联想，并在检测结论里说明「这个模型没找到、本机装了哪些」，还给出 `ollama pull <模型>` 的补救命令。
- **推荐不再重复出现（v1.25.0）**：工具 → 智能推荐 → 推荐范围与偏好 新增「**已经推荐的 [N] 轮内不再重复出现**」（0–50 轮，`0` = 不限制，默认 3）。每点一次「换一批」或每次进推荐页算 **1 轮**，同一批作品在 N 轮内不会再次出现；页面实时显示「已记录 N 轮 / 当前避让 M 部」，并可一键**清空推荐历史**。**这同时是一个根因修复**：v1.24.0 起的避让集合（`exclude`）算出来了却一直没在候选池里用上，导致「换一批」实际从未生效；且退出推荐页再进来（page 回到 1）永远看到同一批。
- **工具箱新增「标签优化」（v1.25.0）**：工具 → 标签优化，对 `.nfo` 的**标签（`<genre>`）**&#x505A;**补全 + 日语转中文**。范围可选 **单一文件 / 文件夹 / 媒体库**；算法可选 **普通智能算法**（纯本地规则 —— 内置日汉词典 + 标题关键词 + 片商 / 系列伪标签 + 全库标签共现，零依赖）或 **AI 智能算法**（在普通算法之上叠加**本地离线 Ollama**，不可用时自动降级，用哪个模型与「智能推荐」页共用设置）。**流程刻意分成两段**：先「扫描并预览」把每个文件「原有标签 → 将新增 / 日语→中文」列成表，核对后点「执行写入」才落盘（点前弹确认）。写入**只改 `<genre>` 节点**（演员 / 评分 / 图片引用 / 简介 / uniqueid / 缩进一律不动），并可在写入前另存 `*.nfo.bak-<时间戳>`；「日语转中文」另提供**是否覆盖源日语标签**的选项（不勾 = 保留日文再补一条中文，两种写法都能搜到）。写完同步库里的 `media.genres`。
  - 词典刻意**对齐你库里真实在用的中文写法**（按真机频次统计）：`中出し → 中出`（库内 22,545 次，而不是「内射」）、`単体作品 → 单体作品`（27,899 次）、`大乱交 → 滥交`、`デカ尻 → 巨尻`… 并整串收录了 `A·B` 形式的**复合标签**（`キス·接吻 → 接吻`、`寝取り·寝取られ·ＮＴＲ → 寝取`）。真机前 400 个高频日语标签里，**能译的 83.7% 都落在库里已有的词上**，不会把词表撕成两半。
- **12 种高亮色 + 选中外发光（v1.25.0）**：工具 → 个性化 → 外观 新增**高亮色**色板（朱红 / 绯粉 / 杏橙 / 鎏金 / 竹青 / 青碧 / 天青 / 靛蓝 / 紫棠 / 藕荷 / 玉白 / 石墨）—— 卡片选中描边，以及按钮 / chip / 滑块 / 勾选框 / 进度条的强调色**整套一起换**（QSS 走令牌替换，自绘控件走 `ACCENT_RGB`；明暗档用 HLS 派生、保留色相，朱红浅档逐字节复现原 `#e05243`）。选中卡片除原有描边外，再叠一层 **`QGraphicsDropShadowEffect` 外发光**（blur 38 / offset 归零 = 四周均匀），光晕真的**溢到卡片之外**，不再是「画在控件内部、被裁掉」的内发光。
- **首页快捷筛选有选中态（v1.25.0）**：首页顶部「最近添加 / 我的收藏 / 合集」三个快捷筛选改为**可选中**（独立的 `#Seg` 样式），选中是**实心强调底 + 亮描边 + 加粗白字**，一眼能看出「点了这个」；同一时刻只有一个亮着，**再点一次同一项即取消筛选**回到全部作品。
- **数据导出 / 导入页间距（v1.25.0）**：该页分组内层行距与勾选区行距统一为 10，勾选框不再与下方按钮行贴在一起。
- **侧栏「实时状态」（v1.27.0）**：侧边栏底部 —— 上面是「**数据统计**」（电影 / 剧集 / 分集 / 演员，两行），下面一块「**实时状态**」：**CPU / 内存 / GPU 三条横条**实时显示占用百分比（≥60% 转琥珀、≥85% 转警示橙，颜色跟随「外观 → 高亮色」），再加「**网络 · Ollama**」（一个状态点同时表示有没有网、Ollama 在不在跑）与「**当前使用模型**」（就是 `ollama list` 里要用的那个，未装会给提示）。采集走**零硬依赖降级链**（psutil → ctypes → `nvidia-smi`），全在后台线程跑，不拖界面；设 `LMC_NO_SYSMON=1` 可关闭。
- **品牌更名「流明盒 / LumaCrate」（v1.27.0）**：原名「本地影视中心 / LocalMediaCenter」。Slogan：**所有流明 · 尽收盒中**（*Every lumen, in one crate.*）。中英文名写在 `src/version.py` 一处（`APP_NAME` / `APP_NAME_EN` / `SLOGAN_CN` / `SLOGAN_EN`），侧栏、窗口标题、启动画面、「关于」、exe 产物名一起跟着变。
- **磨砂玻璃外观**：当前作品的剧照被强模糊后作为整窗底衬，叠加半透明玻璃面板，随浏览内容联动；工具里可切换「磨砂玻璃 / 经典暗色」与低·中·高浓度。
- **面向海量数据的底层优化（v1.14.0）**：为 5 万+ 影片规模做了深度调整 ——
  - SQLite 开启 **WAL**（读写不再互相阻塞）＋ 16MB 页缓存 ＋ 256MB 内存映射 ＋ 15s busy timeout；
  - **连接按线程复用**（原来每个操作都 `connect()`/`close()`），扫描入库不再反复开关数据库；
  - 补齐 **筛选 / 排序 / 关联查询**用到的索引：`library / favorite / year / added_time / added_date / premiere / rating / user_rating / sort_title / file_path / collection / (library,kind) / media_people.media_id / media_people.person_id / people.role_type`；
  - 列表查询改为**列投影**：列表**不取 `plot` 等大字段**（详情面板需要时按主键单行取回），内存占用显著下降；
  - 演职员关联（演员卡小字 / 首页演员列）**只查当前真正要显示的那批 media_id**，不再每次把整张 `media_people`（数万 × 数人）拉进内存；
  - 首页列表**分批填充**（每批 200 行，批间交还事件循环）并在底部显示「正在载入列表… x / y」；
  - 海报 / 头像**带缓存**（原先是每建一张卡就重新读盘并缩放）。
- **媒体库留档**：数据存于 `index_data/media_center.db`，演员索引独立持久化；运行日志在 `index_data/logs/`。

## 使用方式

1. 运行 `流明盒-<版本>.exe`。
2. 左侧「媒体库」组点 **＋ 新建媒体库**（或 工具 → 服务管理 → 媒体库）自己建一个库：填名称、选类型、加上媒体文件夹。
3. 在该媒体库上**右键 → 扫描**（新增/补缺/覆盖三种模式；扫描前先确认数量、再显示进度），或点右上角「扫描媒体库」直接选目录；右键「删除」可移除媒体库（不会动磁盘文件）。在「文件夹」页也可对媒体库**右键**直接扫描。
4. 左侧导航：首页 / 最近播放 / 我的收藏 / 智能推荐 / 文件夹 / 合集 / 分类（全部 / 演员库 / 导演库）/ 媒体库。正在扫描的库，名字右侧会有个**圆形进度环**。
5. 首页为「列表 + 详情」：点击「列设置」勾选显示列，**拖动条目或表头**调整列顺序；鼠标悬停某行会弹出缩略图预览卡。
6. 点击海报进入 **Emby 风格详情页**：全宽背景图 + 简介 + 画质徽章 + 圆形演员行 + 文件信息；标题上方是操作行 —— **播放 / 收藏 / 评分 / 刷新 / 更多**（点「播放」调用本地播放器；点「刷新」只重读**本片**的 nfo 并刷新本页，用于外部工具改过 nfo 之后）。海报卡片本身也带两个角标按钮：**右下角 ▶ 直接播放**（不进详情页）、**左下角 ★ 一键收藏**（金色实心 = 已收藏，白描边空心 = 未收藏），各页面的卡片都有。
7. 顶部搜索框（`Ctrl+K`）可按片名 / 类型 / 演员检索，`片名@演员` 可指定演员。
8. 工具 → **画像概览**：点「开始分析」看清自己的口味分布；工具 → **智能推荐**：选「普通智能算法」或「AI 智能算法」（后者需本机跑着 Ollama，没有会自动回退），在「**调用模型**」里填想用的模型名（就是 `ollama list` 第一列那个，留空 = 自动取本机第一个；点「读取本机模型」可直接挑），再设「**已经推荐的 N 轮内不再重复出现**」（`0` = 不限制），并用「向量编辑」手工加 / 减某类关键词的权重。
9. 工具 → **演员刮削**：选好数据源与策略后点「开始刮削」，为演员库补齐生日 / 别名 / 简介 / 头像；工具 → **个性化 → 外观**：切换「磨砂玻璃 / 经典暗色」与玻璃浓度。
10. 工具 → **重复检测**：选媒体库（默认全部）与最低置信度 → 点「开始检测」（**每次都会清空上次结果重新算**，磁盘上已不存在的文件不会再出现在结果里），结果按**可回收空间**倒序排列，**展开可看每一份**所在目录 / 体积 / 时长，**双击一条即在资源管理器里定位**，可导出 CSV / JSON 清单。清理请**自己在资源管理器里核对后删除**，本功能只做检测、绝不自动删文件。
11. 工具 → **数据与日志**：可**勾选分类**（影片索引 / 演员与导演资料 / 影片收藏 / 用户评分 / 演员收藏…）后**只导出所选**，也可以整库导出为 zip 备份（日后可导入恢复，含 `sections.json` 的包会**合并**进当前库）；出问题时**导出日志**压缩包用于排错。
12. 工具 → **标签优化**（v1.25.0）：选**处理范围**（单一文件 / 文件夹 / 媒体库）与**优化方式**（普通智能算法 / AI 智能算法），点「**扫描并预览**」—— 这一步**只读不写**，会把每个 nfo 的「原有标签 / 将新增 / 日语→中文」列成表；核对无误再点「**执行写入**」（会先弹一次确认，默认先备份成 `*.nfo.bak-<时间戳>`，可关）。勾上「**日语标签转中文**」后，再决定是否「**用中文覆盖原日语标签**」—— 不勾 = 保留日文并另补一条中文（两种写法都能搜到）。
13. **媒体库 / 演员库 / 导演库的筛选与排序**：进入任一媒体库（或「全部」「我的收藏」「合集」）后，页面上方有一条工具栏 —— 左边「排序：…」按钮点开可选排序字段与升降序，右边各下拉可按**收藏情况 / 用户评分 / 年份 / 类型 / 画质**（演员库、导演库为 收藏情况 / 置顶 / 状态 / 头像）筛选，点「重置」清空。选择会被记住，下次打开自动沿用。大数据量时顶部会显示读取进度，滚到底部或点「加载更多」继续载入。
14. **工具窗口是非模态的**：可以一边开着工具一边照常浏览影片；工具里的媒体库扫描在后台进行，进度就显示在「扫描全部媒体库」按钮下方，不会弹窗打断。正在扫描的媒体库在侧栏名字右侧会亮起**圆形进度环**。

## 相关项目 · NFO 画像矿工

**NFO 画像矿工（NFO Profiler）** 是本软件的姊妹项目，也是一个**原生桌面窗口**工具：从 KODI / tinyMediaManager /  
Emby / Jellyfin 生成的海量 `.nfo` 中提取全部有效信息，生成**可视化用户画像报告**，梳理**高频标签 / 艺人 /  
片商 / 系列 / 导演**，并支持 CSV / JSON / XLSX / Markdown / HTML 一键导出。

> **NFO 画像矿工已经满足了前期设计的初衷** —— 即「把散落在数万个 `.nfo` 里的个人观影偏好挖出来、看得见」。  
> 因此该项目不再继续扩张功能；**后续更多的功能会转移到本项目（流明盒 LumaCrate）继续更新和追加** ——  
> v1.23.0 移植了它的**重复影片检测**（跨目录重复识别 + 同目录分片排除 + 可回收空间估算），  
> v1.24.0 又移植了它的**画像概览**（八维偏好雷达 / 高频榜 / 分布 / 标签共现）、**智能推荐**  
> 与**向量编辑**（手工调整推荐维度权重）。

- **GitHub**：<https://github.com/zouzuo1994321/nfo_profiler>
- **当前版本**：v1.6.0（Build 2609170008）· MIT 协议 · 核心零第三方依赖（界面需 PySide6）

两者的分工是：**NFO 画像矿工负责「分析你的收藏」（画像 / 统计 / 报告），流明盒负责「管理与观看你的收藏」  
（海报墙 / 演员库 / 详情 / 播放）**。涉及管理、浏览、播放的新需求，请关注本项目。
